# K230任务框架总结

## 1. K230的系统定位

K230只作为**视觉感知上位机**，负责把摄像头图像转换为结构化道路信息。

K230不负责：

* 电机PWM输出；
* 左右轮速度闭环；
* 房间路线选择；
* 当前路口应该左转还是右转；
* 90°、180°转弯控制；
* 到达房间和返回药房的任务状态机。

完整控制链为：

```text
摄像头
  ↓
K230视觉识别
  ↓ UART
MSPM0路线决策和运动控制
  ↓
编码器速度闭环
  ↓
电机
```

---

## 2. K230的核心任务

K230需要持续完成以下工作：

```text
采集图像
→ 提取道路区域
→ 识别左右黑色边界
→ 计算道路中心
→ 计算车辆相对道路的偏差
→ 识别左右支路和路口
→ 评估识别可信度
→ 发送给MSPM0
```

K230输出的是“看到了什么”，而不是“车辆应该怎么走”。

例如：

```text
左侧存在支路
右侧不存在支路
道路中心偏右
道路方向向左倾斜
路口距离车辆约25cm
当前识别可信度为90%
```

是否在这个路口左转，由MSPM0根据目标房间和当前路线阶段决定。

---

# 3. K230内部功能分层

建议将K230任务划分为五层。

## 第一层：图像采集层

负责：

* 摄像头初始化；
* 获取稳定图像；
* 设置固定分辨率和帧率；
* 控制曝光、白平衡等摄像头状态；
* 向后续模块提供最新图像。

这一层只负责获得图像，不理解道路。

---

## 第二层：道路预处理层

负责把原始图像转换成适合道路分析的数据：

```text
原始图像
→ 道路ROI裁剪
→ 黑色区域提取
→ 图像去噪
→ 鸟瞰或统一坐标变换
```

这一层需要尽量排除：

* 车体自身黑色部件；
* 地面污渍；
* 阴影；
* 门口黑白虚线；
* 画面边缘无关黑色结构。

---

## 第三层：道路几何层

负责提取道路的连续几何信息，包括：

* 左侧道路边界；
* 右侧道路边界；
* 当前道路宽度；
* 道路中心线；
* 横向偏差；
* 航向偏差；
* 单边界或双边界状态。

推荐统一使用车体坐标系表达：

```text
X轴：车辆正前方
Y轴：车辆右侧
```

这样下位机不需要知道摄像头具体安装高度和偏移。

---

## 第四层：道路结构识别层

负责识别地图中的结构事件：

* 左支路；
* 右支路；
* 十字或道路扩展区域；
* 道路终点或房间入口区域；
* 路口相对车辆的位置；
* 路口是否已经通过。

这一层只报告结构，不进行路线决策。

例如：

```text
LEFT_BRANCH = 1
RIGHT_BRANCH = 0
```

而不是：

```text
TURN_LEFT
```

---

## 第五层：通信和状态管理层

负责：

* 将视觉结果封装成通信帧；
* 周期性发送给MSPM0；
* 维护帧序号；
* 响应MSPM0的模式切换；
* 报告视觉异常；
* 防止旧数据被重复当成新数据。

---

# 4. K230运行模式

建议K230具备三个主要模式。

## 空闲模式

```text
IDLE
```

用途：

* 车辆尚未启动；
* 不执行高频道路识别；
* 等待下位机命令；
* 可以显示调试画面。

---

## 数字识别模式

```text
NUMBER
```

用途：

* 识别1～8号目标房间；
* 将房间号发送给下位机；
* 等待下位机确认。

第一阶段练习视觉循迹时可以暂时不使用该模式，目标房间由按键选择。

---

## 道路循迹模式

```text
TRACK
```

用途：

* 持续识别左右黑线；
* 输出横向偏差和航向偏差；
* 识别左右支路；
* 输出路口距离和可信度；
* 持续发送视觉帧。

---

# 5. K230输出的数据内容

每一帧视觉结果至少应包括：

| 数据    | 含义            |
| ----- | ------------- |
| 帧序号   | 判断是否为新图像      |
| 横向偏差  | 车辆偏离道路中心的程度   |
| 航向偏差  | 车辆朝向与道路方向的差异  |
| 左边界有效 | 是否识别到左侧黑线     |
| 右边界有效 | 是否识别到右侧黑线     |
| 左支路存在 | 是否观察到左侧分支     |
| 右支路存在 | 是否观察到右侧分支     |
| 路口距离  | 路口相对车辆的前向距离   |
| 道路宽度  | 辅助判断路口和识别异常   |
| 可信度   | 当前结果是否可靠      |
| 异常状态  | 模糊、遮挡、过曝或识别退化 |

通信内容可以抽象为：

```text
[跟踪帧, 帧号, 横向偏差, 航向偏差,
 道路宽度, 道路结构标志, 路口距离, 可信度]
```

---

# 6. 道路循迹数据框架

K230不直接计算左右轮输出，而是向下位机提供两个主要控制依据。

## 横向偏差

表示车辆是否偏离道路中心：

```text
横向偏差 > 0：道路中心在车辆右侧
横向偏差 < 0：道路中心在车辆左侧
```

## 航向偏差

表示车辆当前朝向与道路延伸方向的差异：

```text
航向偏差 > 0：道路方向向车辆右侧倾斜
航向偏差 < 0：道路方向向车辆左侧倾斜
```

下位机结合这两个误差计算转向控制量。

---

# 7. 边界识别框架

## 双边界有效

正常工作状态：

```text
左边界有效
+
右边界有效
→ 计算道路中心和道路宽度
```

这种状态可信度最高。

---

## 单边界有效

如果只识别到一侧黑线，K230可以根据历史道路宽度估算道路中心：

```text
只看到左边界
→ 根据历史道路宽度估算右边界

只看到右边界
→ 根据历史道路宽度估算左边界
```

但需要：

* 降低可信度；
* 标记为降级状态；
* 不确认路口；
* 不能长时间持续使用。

---

## 双边界丢失

如果左右边界都无法识别：

```text
输出视觉无效
→ 通知下位机
→ 下位机减速或停车
```

K230不能把双边界丢失直接解释成路口。

---

# 8. 路口识别框架

路口判断应由多个视觉特征共同完成：

* 道路宽度明显增加；
* 左侧出现向外延伸的黑线；
* 右侧出现向外延伸的黑线；
* 远处出现新的道路区域；
* 连续多帧结构一致；
* 路口位置随车辆运动逐渐接近。

K230输出的路口过程可分为：

```text
未发现路口
→ 远处发现路口
→ 路口持续接近
→ 路口到达转弯参考位置
→ 路口通过
```

这样下位机可以区分：

* “已经看到路口”；
* “车辆已经到达适合转弯的位置”。

---

# 9. 转弯阶段的K230任务

90°或180°转弯由下位机和编码器控制，K230不参与转弯闭环。

在转弯期间，K230可以继续识别，但输出应标记为：

```text
转弯中，循迹结果暂不可用
```

转弯结束后，K230进入道路重捕获阶段：

```text
转弯结束
→ 搜索新道路
→ 先找到一侧边界
→ 找到双边界
→ 连续多帧稳定
→ 报告道路重新有效
```

下位机收到稳定视觉结果后，再恢复正常行驶。

---

# 10. 可信度和异常管理

K230应对每帧结果计算可信度。

可信度可以综合：

* 左右边界点数量；
* 边界拟合误差；
* 道路宽度是否合理；
* 边界是否连续；
* 与上一帧变化是否合理；
* 图像是否模糊；
* 光照是否异常；
* 路口结构是否稳定。

视觉状态建议分为三级：

## 正常

```text
边界稳定
可信度高
结果连续
```

正常发送。

## 降级

```text
只有一侧边界
局部遮挡
可信度下降
```

继续发送，但带降级标志。

## 无效

```text
边界完全丢失
图像严重模糊
结果跳变异常
```

发送视觉无效状态，下位机负责停车。

---

# 11. K230与下位机的交互框架

## MSPM0发给K230

主要是模式命令：

```text
进入空闲模式
进入数字识别模式
进入道路循迹模式
任务结束
视觉复位
```

也可以附带当前运动阶段：

```text
正常直行
接近路口
正在转弯
转弯后重捕获
```

这些信息可以帮助K230选择不同的识别策略，但不能把路线决策交给K230。

---

## K230发给MSPM0

主要包括：

```text
模式准备完成
识别到房间号
道路跟踪数据
左/右支路信息
视觉降级
视觉丢失
道路重新捕获
```

---

# 12. 推荐的K230任务主循环

从架构上可以概括为：

```text
系统初始化
    ↓
等待下位机模式命令
    ↓
根据模式执行视觉任务
    ↓
采集最新图像
    ↓
道路预处理
    ↓
边界和道路中心提取
    ↓
路口结构分析
    ↓
可信度评估
    ↓
生成视觉结果
    ↓
发送给MSPM0
    ↓
进入下一帧
```

道路循迹模式可以进一步表示为：

```text
TRACK模式
    ↓
双边界有效？
 ┌──是──────────────┐
 │                  │
计算中心和航向      否
 │                  ↓
分析支路和路口   单边界有效？
 │              ┌──是──────┐
计算可信度       │          │
 │          估算道路中心    否
 │              │          ↓
发送正常帧    发送降级帧  发送无效帧
```

---

# 13. 安装条件在架构中的影响

K230视觉框架默认：

* 摄像头朝车辆前进方向；
* 摄像头位置和角度固定；
* 镜头接近车体纵向中心；
* 能同时看到左右道路黑线；
* 能看到近场、中场和远场；
* 摄像头输出转换到车体坐标系；
* 车体自身黑色结构不会进入主要检测区域。

摄像头固定偏移可以通过K230内部坐标转换处理，但摄像头运行中晃动会直接破坏整个视觉控制架构。

---

# 14. 最终职责边界

可以把整个K230任务浓缩为一句话：

> K230负责把道路图像转换为“车辆相对道路的位置、方向、路口结构和识别可信度”，MSPM0根据这些信息完成路线选择、运动控制和任务执行。

最终分工如下：

| 功能       | K230 | MSPM0 |
| -------- | ---: | ----: |
| 摄像头采集    |    是 |     否 |
| 黑线提取     |    是 |     否 |
| 道路中心计算   |    是 |     否 |
| 横向和航向偏差  |    是 |     否 |
| 左右支路识别   |    是 |     否 |
| 路口距离估计   |    是 |     否 |
| 房间路线选择   |    否 |     是 |
| 决定左转或右转  |    否 |     是 |
| 速度目标计算   |    否 |     是 |
| 编码器闭环    |    否 |     是 |
| 电机PWM    |    否 |     是 |
| 转弯和停车    |    否 |     是 |
| 视觉失效安全处理 | 报告异常 |  执行停车 |
